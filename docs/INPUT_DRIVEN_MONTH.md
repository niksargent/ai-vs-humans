# Input-driven month — model 0.9

## User contract
Every update failure is generated by visible world settings. Pace zero produces no updates. There is no project power switch and no hidden starting bad update. Other expressly selected agent, health and misinformation threats remain independent.

## Calculation
Up to 20 updates/day, limited by the minimum of pace, compute and experiment capacity. Testing handles up to four/day. Each project receives fixed named draws for a mistake and detection. Mistake rate determines potentially network-breaking faults; testing effectiveness determines whether a tested mistake is caught. Caught mistakes are withheld. Untested projects wait if Test before release is selected, otherwise may go live. Permission gates all releases. Any released fault adds a full repair job to each reached region. Existing reserves, supplies and relief budgets carry over. Same settings and seed give identical board/month results.

Project IDs preserve error draws while pace varies. Which projects receive tests can change as the queue changes. Faster pace does not guarantee a strictly worse outcome in every individual replay. Regional shared dependencies remain fixed per month. Each escaped fault can enter the authored false-warning/human-decision route; these are not empirical incident probabilities. Release history ends at nuclear use; devastation is not simulated.

## Interface
The toolbar displays produced → mistakes → caught → escaped, opening the development ledger. The ledger lists each escaped update by day and project number, explains whether testing missed it or it was unchecked, and links into communications. The board shows cumulative monthly damage, not the isolated contribution of a selected update. World settings exposes mistake rate and testing effectiveness. Scenarios reset actual settings and show their change receipt. Updates go wrong replaces One bad update.

## Compatibility
Version bumped to 0.9. Old saved worlds keep numerical settings, receive the new mistake/testing defaults and are recalculated with an explicit migration notice. Removed researchEnabled/faultyChange flags are discarded. Old monthOptions are accepted for file compatibility but no longer override world controls. Zero pace is the only project off condition. Numeric parameters are illustrative, not estimates of real AI risk.

## Validation
97 tests: queue conservation including caught mistakes, zero pace/compute/permission, 600-update production ceiling, stable project draws across pace changes, exact error/detection boundaries, board/month identity, six educational outcome categories, delayed faults, cumulative repair and stock conservation, existing service/continuation checks. Former single-incident exact-depletion tests exercise the recovery primitive directly; monthly integration tests check cumulative work and supply conservation.

Browser verification: reset produces 120 updates / 12 mistakes / 1 caught / 11 escaped at seed 42; each dated failure opens its own explanation. Pace Home yields zero updates and a holding world. Undo restored the user’s 65 pace, advice-only, isolated-world settings. Month worker returned 128 quiet replays for that protected world, with no console errors.
