## Evidence policy

Each causal edge needs its own claim, source section, supporting observation or argument, limitation, applicability and review date. A source supporting a general hazard does not validate the entire chain or its numerical coefficients. The labels are **observed**, **supported mechanism**, **conditional extrapolation**, and **illustrative assumption**; these are evidence categories, not numerical probabilities.

The supplied report's embedded citation tokens are not usable publication references. Preserve that report, but replace tokens with verified direct links in the app's evidence library. No evidence badge should appear merely because a source was listed in the report.

## JEV investigation

The user has signed up and raised JEV as an option for fast decisions from state. No JEV skill was found in the searched local skill roots. A public [building-with-jev skill](https://github.com/dbreunig/building-with-jev-skill/blob/main/skills/jev/SKILL.md) was found and read as reference material. It has not been installed or executed; no account or credential was accessed.

The public skill describes small independent judgments, with arithmetic and policy controlled by code. That is compatible with a narrow semantic routing role. The primary vendor documentation is the authority for API behaviour; the public skill is guidance from its repository author, not proof of calibration for this domain.

Decision: do not use JEV to fill unknown causal probabilities, decide whether war happens, or generate collapse classifications in the core. Potential later experiment: map a visitor's question onto an existing explanation, using a labelled test set and an abstention/fallback path. No install or API integration is needed for specification work.

Keep the user's OpenAI-via-Cloudflare pattern for any future OpenAI runtime feature. Clarify the provider route if a JEV feature is actually selected. Do not presume that access to one provider authorises a different integration architecture.

## Research process

For each pathway, seek both supporting mechanisms and the strongest relevant limiting evidence. Record publication date and scope, distinguish controlled evaluation from real deployment, and avoid converting normative recommendations into statistical facts.

Create an edge register before implementing release transitions. Each row links the exact model edge to its evidence category and rule. Numerical parameters require a source or an explicit illustrative label. Where reasonable alternative models disagree, preserve that disagreement in the scenario comparison rather than selecting the most dramatic result.

Domain review is desirable for military escalation, public health and extinction continuations. Lack of review should be disclosed as a limitation, not disguised by polished graphics. Real user comprehension testing is separate and will be organised by the user.
